## Defect 1 — open_debate never shows peers (confirmed)
`run_open_debate` sets `ctx.revealed_materials = dict(revealed)` before each agent runs, but `LLMInvestigator.run` (investigators.py) calls `context.to_prompt_block(revealed=False)` unconditionally, so peer conclusions are silently dropped from every prompt.

Red test: with a mock LLM client that returns conclusions derived from whether the prompt contains a `# PEER MATERIALS` block, run `run_open_debate` and assert later agents' prompts DID contain earlier agents' conclusions. Must FAIL today.

Fix (additive, backward compatible): give `InvestigationContext` an opt-in flag (e.g. `peer_visibility: bool = False`) or add a `share_peers` param to `build_context`; `to_prompt_block(revealed=...)` renders peer material when flagged; `LLMInvestigator.run` passes `revealed=<ctx peer flag>`. `run_open_debate` opts IN; `run_single_agent`, `run_fixed_dag` (its prior-stage sharing is an explicit DAG feature — keep behavior, but route it through the same mechanism), `run_isolated_vote` and the full protocol path (`RepliClawProtocol`) stay at the default (blind). The `to_prompt_block(revealed=False)` hardcode in `LLMInvestigator.run` must respect the context flag instead of being a constant.

Also add a red-then-green adversarial peer-pressure test (DeterministicInvestigator or mock): a deterministic investigator's conclusion must NOT change merely because peer conclusions differ — the debate mechanism exposes peers to the LLM layer, and the deterministic backend must either respond to peer material in a controlled, testable way or explicitly ignore it (document which in the test).

## Defect 2 — isolated_vote uses the full verdict engine, not simple majority voting (confirmed)
`run_isolated_vote` computes `agreement` via `RepliClawProtocol._agreement` (informational) but then `_finalize` runs `compute_verdict(...)` — the full shared evidentiary logic — so "isolated vote" is not a simple vote at all.

Red test: construct 3 isolated findings with 2×`refuted`, 1×`supported` on a claim whose evidence would make `compute_verdict` return something other than the 2-of-3 majority (e.g. via executable flags/confidence skew), assert the strategy verdict label equals the strict majority outcome. Must FAIL today.

Fix: implement a pure majority rule inside the strategy (new private helper in `strategies.py`): strict majority of the three conclusions → that label; tie or abstention plurality → `INCONCLUSIVE`. Use it as the verdict for `isolated_vote` ONLY (a small `Verdict` construction with reason noting "simple majority vote; no adjudication"). Record `vote_counts` in the `agreement` dict. Do NOT change `compute_verdict` or the other four strategies.
