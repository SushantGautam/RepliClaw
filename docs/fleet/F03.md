Create ≥8 new held-out fixtures with genuinely different shapes/domains from the dev set (different n, different fault types incl. ones NOT in the dev set, supported + refuted truths). 2. **Leak guard**: red test — build a claim from a fixture, serialize exactly what an investigator can see (claim statement + `data` dict + context blocks), assert `reference_truth` and `seeded_fault` never appear in any serialized view (check `Claim` field exclusion in `to_prompt_block` paths AND a deep string scan of `claim.data`). Also add an eval-level guard: `evaluation.run_eval(...)` must strip benchmark-only fields from claims before running and fail loudly if they ever surface in a run's prompts/evidence.
3. **Budget parity (paired design)**: red test — for a strategy set, the eval records per (task, strategy) budget: investigator count, LLM call count, token usage (deterministic backend: 0 tokens — that's fine; parity is about equal investigator counts and equal data access, asserted per task). Assert every strategy got the same number of investigators on every task (3/3/3...) and same allowed data. Document the token-cap mechanism: `investigator_factory` must accept a budget token the runner threads through; keep it optional/backward-compatible.
4. **Paired comparisons + CIs**: implement `paired_diff(a_rows, b_rows, task_id)` and `bootstrap_ci(paired_scores, n_boot=2000, seed=13)`: correct per-task, McNemar-style exact binomial test for correctness pairs (no scipy — implement exact binomial by hand with math.comb), and a bootstrap CI (seeded, reproducible) for the paired score difference. Red test: known paired dataset produces the exact expected p-value/CIs (compute expected values with an independent small script before pinning).
5. **Honest recovery metric**: red test — the new `recovery_transition` metric requires an OBSERVED pre-followup error → post-followup correct transition: it needs per-run "initial" (pre-need) and "final" (post-need) labels. Extend the benchmark row schema ADDITIVELY (`initial_label`, `final_label` — existing keys unchanged; `recovered` keeps its old meaning, add `recovered_transition`). A run where the strategy was right all along is NOT a recovery; a run where it was wrong and stayed wrong is NOT a recovery; only wrong→correct counts (report `n_wrong_start`, `n_recovered`, `recovery_rate` with explicit denominator). If a strategy's runner does not expose a pre-need label yet, record `initial_label=null` and the metric reports `n/a` rather than guessing — do not fake it.
6. **No-Live-LLM-by-default**: `run_eval` must work fully offline with the deterministic factory (it will — keep it that way) and must REFUSE a live factory unless an explicit `allow_live=True` flag AND a budget cap are set. Red test for the refusal.
7. Run the eval on the held-out set with the deterministic factory, all 5 strategies, and save the report to `artifacts/evaluation/heldout-deterministic/` (committed JSON + MD summary). Numbers in the report are whatever they actually are — including ties or losses; state them plainly.
