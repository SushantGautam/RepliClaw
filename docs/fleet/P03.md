## Mission
Implement the evidence-escrow mechanism: independent agents privately commit
to falsifiable prediction packets BEFORE any peer's unpublished content or
intervention outcome is visible; after a phase boundary, reveals are verified
against commitment hashes and published. This is the G3 gate: "reliable
evidence escrow: two agents independently precommit before peer information;
tamper/phase tests."

The contract is FROZEN: `docs/design/EESS_CONTRACTS.md` §1 (prediction
packet + commitment), §2 (events.jsonl), §3 (evidence observation). Code to
it exactly. The scientific claim escrow must support (and later P08 will
test): preventing premature social influence — pre-reveal isolation is the
mechanism under test, so the negative tests here are the product, not
ancillary.

## Required API (pydantic v2, mirroring repo style — read `src/repliclaw/models.py` for conventions)
Package `src/repliclaw/escrow/`:
- `packet.py`: `PredictionPacket` (fields per contract §1; `schema` constant
  `"repliclaw.prediction_packet/v1"`), `canonical_bytes(packet) -> bytes`
  (sort_keys, separators (",",":"), UTF-8), `commitment_hash(packet) -> str`
  (sha256 hex of canonical bytes), `PacketCommitment` (public projection:
  packet_id, agent_id, case_id, commitment_sha256, committed_at, phase,
  hypothesis_id, intervention_id — assertion: canonical_bytes of the
  commitment projection must NOT contain the statement/prediction bytes).
- `phase.py`: `PhaseGate` — phases are an ordered enum
  `COMMIT -> REVEAL -> EXECUTE -> RESOLVE`; `PhaseGate.assert_can(agent,
  action, phase)` raises `PhaseViolation` for out-of-order actions; the gate
  is PER-RUN (monotonic, one forward transition at a time, recorded as
  phase_transition events).
- `ledger.py`: `EscrowLedger` rooted at a `Path` (append-only JSONL:
  `commitments.jsonl`, `events.jsonl` per contract §2, `evidence.jsonl` per
  §3). Methods:
  * `commit(agent_id, packet) -> commitment` (only legal in COMMIT phase;
    stamps committed_at=monotonic clock; stores FULL packet privately under
    `private/<agent_id>/` files — the public jsonl gets the projection only)
  * `open_reveal(case_id)` (phase transition COMMIT->REVEAL)
  * `reveal(agent_id, packet) -> RevealResult` (recomputes hash; mismatch →
    `reveal_mismatch` event, result.status = "mismatch", packet NEVER
    published; match → `reveal_verified` event, packet published)
  * `publish_evidence(observation)` (EXECUTE/RESOLVE phases only; rejects
    observations whose `data` contains interpretation-only keys? NO — keep
    it mechanical: require `provenance.run_id` + `provenance.config_sha256`;
    schema violations raise)
  * `snapshot() -> dict` (content-addressed: sha256 of canonical dump — used
    by P04's counterfactual replay; MUST be deterministic for same history)
- `tamper.py` (or within ledger): `verify_ledger(root) -> list[Violation]`
  re-checks every commitment/reveal pair from disk (append-only file
  integrity: line count, seq monotonicity, hash chain over events).

## Red tests to write FIRST (then make green)
1. `test_two_agents_independent_precommit`: two agents commit in COMMIT
   phase; before `open_reveal`, agent B cannot read agent A's packet via any
   ledger public API (assert the public projection does not contain
   statement/prediction/competing_explanation bytes — test at byte level on
   the jsonl files on disk).
2. `test_reveal_verifies_and_preserves`: reveal after boundary publishes
   packet identical to committed content; original commitment hash
   unchanged; `claims.jsonl`-style trace preserved (no hindsight rewrite —
   a post-hoc "amended" packet with same packet_id raises).
3. `test_tampered_reveal_mismatch`: reveal a mutated packet (one character)
   → `reveal_mismatch` event, nothing published, ledger still usable.
4. `test_phase_violations`: commit after REVEAL → PhaseViolation; publish
   evidence in COMMIT phase → PhaseViolation; reveal before boundary →
   PhaseViolation.
5. `test_events_monotonic_and_append_only`: seq strictly increasing; two
   ledger processes appending to the same root interleave without corrupting
   lines (use two Python processes or threads; verify every line parses).
6. `test_snapshot_deterministic`: same action sequence → same snapshot hash;
   different sequence → different hash.
7. `test_verify_ledger_catches_tampering`: hand-edit an events.jsonl line
   (change a hash, reorder) → verify_ledger reports violations.
