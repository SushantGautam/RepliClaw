## Contract
1. `ExecutionRecord` (pydantic, in `execution.py`): fields `command: str`, `cwd: str`, `exit_code: int`, `stdout: str`, `stderr: str`, `duration_s: float`, `started_at: str`, `agent_id: str`, `artifact_hashes: Dict[str, str]` (sha256 of any files the command produced), `env_notes: str`. `verified: bool` + `verify_report: str` produced only by the verifier — NEVER settable by the investigator.
2. `run_python_execution(code, cwd, agent_id, timeout_s=20)` — runs the snippet in a subprocess (`sys.executable -c` or temp script), captures all of the above, computes output file hashes. This is real execution: an exit code from a process, not a self-report.
3. `verify_execution(record, out_dir)` — independent re-check: re-runs the command in a clean temp dir, compares exit_code and stdout (normalized: strip timestamps/paths) and output file hashes. Returns `verified: bool` + human-readable `verify_report`. A record whose stdout/hashes don't reproduce is `verified=False` and the mismatch is quoted in the report.
4. Investigators may now attach `finding["execution"] = record.to_dict()` — but the protocol/verifier alone decides truth: when a finding claims `executable=True`, the EVIDENCE created for it must carry the record and a `verified` stamp. A finding with `executable=True` and NO record, or a record that fails `verify_execution`, gets `Evidence.executable=False` and a warning note (log an event). This is the core inversion: **self-attestation alone can never produce an executable-stamped evidence row.**
5. `DeterministicInvestigator`: its `executable=True` claims must now be backed by actually running its computation through `run_python_execution` (the same math, as a subprocess snippet — this proves the arithmetic end-to-end and makes every deterministic run genuinely executed). Attach the record.
6. Persistence: protocol stores records under the run dir (e.g. `execution/*.json` + stdout files) via RunStore-compatible append; `verify.py`/CLI may surface verification status if trivial (optional, keep minimal).
