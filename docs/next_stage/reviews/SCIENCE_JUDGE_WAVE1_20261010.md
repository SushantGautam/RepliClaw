## 3. Condition-by-condition status

### A3 — MC power re-derivation — **CLOSED (with conditions S2, S8)**
- **Soundness of the re-derivation:** Yes. All headline numbers in the doc match the raw results JSON exactly (type-I Δ=0 N=24 mid = 0.026; powers 0.3456 / 0.5555 / 0.5057 / 0.7314 / 0.6151 / 0.839; null `de_only` false-fires 0.8336 @ s=0.5, 0.5606 @ s=0.5 N=12; achieved θ 0.00183/0.03807/0.07469/0.07589). L5 frozen constants match the statistics protocol verbatim.
- **"Bit-exactness" claim evidence:** The doc's claim is *supported but narrowly* — the L5 function is called **verbatim** (not a vectorized stand-in), a pure-Python **twin** was asserted bit-identical on 40 (cell,rep) pairs, and I **independently reproduced cell 0 bit-exactly** under a pinned numpy 1.26.4 venv. The weakness is provenance (S2: code is uncommitted scratch, no recorded sha) and wording (S8), not correctness.
- **N=24 × k=4, MDE=0.20 as the FROZEN recommendation:** **Defensible and correctly conditioned.** It is the only config in the grid that reaches ~84% power at MDE 0.20 within the 24-case budget (0.839 @ k=4 vs 0.731 @ k=3 vs 0.556 @ k=2). MDE 0.15 is *not* achievable at N=24,k≤4 (0.615 @ k=4; needs N≈55). The doc correctly refuses to silently keep 0.15 and ties the recommendation to the human budget decision. The one caveat: the "N≈55 for 80% power" is a **quadratic fit through N=12–30**, an interpolation, not a direct grid cell — the prereg must cite direct grid cells for the operative MDE and use the fit only for interpolation.
- **S-sat stop rule (either-arm saturation ≥ 25% of pilot cases ⇒ re-stratify):** **The right guard.** It is more conservative than the naive ">50% both arms" heuristic and is justified by the grid: at true Δ=0, one-arm `de_only` saturation produces a false MEANINGFUL_POSITIVE fire of ~83% at s=0.5 (N=24) and **my independent re-simulation at s=0.25 gives 0.20–0.33** — i.e., already a material false-fire well before 25%, so gating at ≥25% is conservative. The doc itself concedes s=0.25 is "already ~30–40% at N=12–24 … right at the A1 floor," which is the honest framing. The rule stops on *either* arm, not just D-E, which correctly handles the case where C-EQ saturates.
- **Retiring the 2-sided normal formula (3.4× off):** **Correct.** The formula uses between-case σ (0.18), but the actual per-case difference statistic has σ_eff ≈ 0.44 (Bernoulli noise across k=2 dwarfs between-case variance; between-case accounts for ~15% of Var(d_c)). MC of the *actual frozen one-sided* rule is the right sole authority. Retiring the formula removes the single biggest remaining route of power overclaim.
- **Remaining route by which power is overclaimed:** Residual assumptions — iid Bernoulli within case, uniform between-case p, no correlated seed failure, no timeout/abstention. The doc flags these in §Limitations and correctly states they can only *decrease* effective k / *increase* effective σ_D (i.e., the numbers are optimistic-ish upper bounds for the between-case part). The operative protection is the **pilot-σ variant cell set** (a 10-line extension, run post-pilot, *before* prereg freeze) — **this is mandatory, not optional**: the prereg power statement must be recomputed with the pilot-estimated σ̂_D. Until then, all power numbers are simulation-only and must carry that label (they do).

### A4 — C-EQ as an honestly-strong adaptive central manager — **CLOSED (with conditions S3, S5)**
- **Does the bounded consultation channel CAP the central manager below a real coordinator (making D-E win by default)?** No — the opposite risk is present and is honestly handled. C-EQ's manager is *more* capable than any single D-E agent: it sees the **union** of all hypotheses' verified evidence + baseline, centrally schedules the same 3 workers (byte-for-byte D-E finding prompts), and can call the **same executable interventions** D-E can. The consultation cap (1/investigator/case, fail-loud, logged) bounds C-EQ's *cross-talking*, but that is a fair parity constraint, not a handicap: D-E's agents are isolated from each other by design (EIG), so C-EQ does not lose any capability D-E actually has. D-E would not win by default from this cap.
- **Is "adaptive" real?** **Yes, but precisely: evidence-adaptive, not feedback-adaptive.** Tracing `run()`: each planner round's prompt is rebuilt from `_wall_free_evidence(self.escrow.evidence())` → `_evidence_block_union`, so round N genuinely conditions on the *machine-verified evidence from every intervention executed in rounds < N* (plus the sealed forecast line and budget-so-far). The loop can `diagnose`-early, `abstain`, or reject an unregistered intervention (traced, no executor call). That is a real feedback loop on *outcomes*. What it is **not**: investigator *reasoning* does not feed back — the 3 findings are collected once, after the loop, and only inform the final diagnosis / defect_class backfill. The prereg must state this precisely (S5) so "adaptive" is not overread as "incorporates the swarm's opinions each round."

### What the Wave-2 pilot MUST cover to be a legitimate bounded **exploratory** pilot (not confirmatory)
The pilot's legal purpose is to **estimate variance and check the S-sat guard**, so the prereg can recompute power with pilot σ̂_D. It is **not** to test the research hypothesis. To stay exploratory:

1. **Segregated cases.** Run on cases **disjoint from the 42 heldout candidates** (and from the 10 smoke cases). The 42 must remain untouched by any pilot-driven tuning. State the segregation in the prereg.
2. **Pre-registered, bounded, small.** Fix the pilot case count and seed count *before* running (e.g., the N=24×k=4 design or a deliberate subset), with a hard ceiling. No adding cases "to see what happens."
3. **Purpose = variance + saturation, not effect.** Report only (a) the **within-case / between-case variance estimate σ̂_D** (to feed the pilot-σ MC variant), and (b) **per-arm saturation fractions** to evaluate the **S-sat stop rule**. **No** effect estimate, **no** power claim, **no** "D-E vs C-EQ" superiority statement.
4. **No confirmatory tuning.** Do **not** tune prompts, arms, scorers, MDE, the Δ_min floor, the S-sat threshold, or stratification *from pilot outcome patterns*. Any such change is a versioned prereg **amendment recorded before the change**, motivated by a pre-registered defect (e.g., a harness bug), never by "the pilot results suggest…".
5. **Frozen config, then recompute.** Freeze prompts/arms/scorer *before* the pilot; after the pilot, run the **pilot-σ MC variant cell set** (the 10-line extension) to recompute the operative power, *then* freeze the prereg. The pilot σ̂_D enters the prereg power statement — it is the one legitimate use of pilot data.
6. **Official baseline = feasibility check only.** The official baseline (e.g., BARO) may be run on the pilot cases **only** to confirm the harness reproduces an official metric in-range (feasibility/sanity) — **not** as a comparison the research claim rests on.
7. **Label discipline.** Same S1 gating applies: the pilot must not read `root_cause.txt`/strata beyond the scorer.
8. **Report saturation honestly.** Per the MC doc's own rule, every pilot result report discloses the saturation fraction (the §4.3 / S-sat disclosure requirement).
