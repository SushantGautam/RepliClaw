### A1.1 Defect in v1.1 (verified against committed code)

v1.1's P1 rule, repeated verbatim at lines 34, 194, 211:

> "S5 succeeds P1 iff bootstrap 95% CI upper bound of the 10-run interim difference (S5 minus S3 on M1) is < 0, i.e. the entire CI is below zero; otherwise P1 fails and the full 20-run set is reported with the CI."

Two independent defects (Hotspots Critical 1; STEER item 1):

1. **Sign-reversed.** M1 is higher-is-better (`score.py::_diagnosis_correct` → `M1 ∈ {0.0, 1.0}`, 1 = correct diagnosis = defect class **and** target artifact). **Code consequence (tracked, not changed by this amendment):** `score.py` lines 445–468 implement exactly the defective rule (computes S5−S3, `decision_branch` labels `hi < 0` → "worsened" as the rule text, scorecard header "P1 decision (S5 vs S3 on M1)"). ## A4 — Post-evidence verdict prompt amendment (condition of the live window)

**Defect (Hotspots Critical 2; STEER item 2):** the live S5/A1/A3 post-evidence RESOLVE verdict prompt states that evidence was observed and includes the agent's own pre-outcome commitment, but it injects **no machine-verified evidence at all** — the LLM's final conclusion is not causally informed by the observed intervention outcomes.

```python
prompt = (
    f"{VERDICT_MARKER}\n"
    f"AGENT_ID: {agent_id}\n"
    f"Evidence has been observed for hypothesis "
    f"{packet.hypothesis_id}. Your pre-outcome commitment was: "
    f"{packet.predicted_outcome!r}. Respond with JSON containing "
    f"conclusion (supported|refuted|uncertain), confidence, "
    f"defect_class, target_artifact, statement."
)
```

**Amendment:** the prompt **must** inject the **machine-verified public evidence view** for that agent's hypothesis, and **provably not** the sealed oracle. The evidence view is built solely from verified public records for the packet's hypothesis: escrow-ledger revealed/verified event IDs, counterfactual-execution run/observation IDs, and per-arm outcome labels (the same records the deterministic selection policies already consume). It must contain no oracle path, no `true_cause`, no oracle field, and no `claim.reference_truth` value.

**Required minimal new prompt shape (normative template):**

```python
prompt = (
    f"{VERDICT_MARKER}\n"
    f"AGENT_ID: {agent_id}\n"
    f"HYPOTHESIS_ID: {packet.hypothesis_id}\n"
    f"Your pre-outcome commitment (sealed before evidence was observed): "
    f"{packet.predicted_outcome!r}\n"
    f"Machine-verified public evidence for this hypothesis "
    f"(verified records only; sealed oracle content is NOT included):\n"
    f"{evidence_block}\n"
    f"Respond with JSON containing conclusion (supported|refuted|uncertain), "
    f"confidence, defect_class, target_artifact, statement, "

# evidence_block: one line per verified record, e.g.
# "- evidence_id=<id> run_id=<run_id> arm=<arm_key> outcome=<outcome_label> snapshot_sha=<sha>"
```

The `evidence_cited` field makes the LLM's claim checkable offline: the report can verify every cited ID exists in the run's sealed artifacts (and flag verdicts that cite nothing or cite unverified IDs).

## A6 — Matched-cap semantics + required negative-path tests

**Normative semantics (re-affirms v1.1 §5.2 line 155):** C1/§5.2 parity (identical envelope hash across all arms of a run-set + same Claim/case + hard abort at the envelope) proves:

1. identical **cap** (same `BudgetEnvelope` ceiling: 60 000 tokens / 900 s / 3 agents),
2. **same task** (same Claim/case instance, C1),
3. **no overrun** (ledger hard-aborts; `aborted_budget` runs excluded per §7.2).

It does **NOT** prove equal **consumption**. Arms may legitimately consume different amounts within the same ceiling; consumption is a scientific **outcome**, measured as **M5** (tokens per run) and **M6** (tokens per correct diagnosis) — never a parity failure. Reports must state "matched-cap + same-task + no-overrun" and must not say "equal budget spent".

**Required negative-path tests (all must exist and be green before run 1; tracked with A4/A1.7 PRs):**
