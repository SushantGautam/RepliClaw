## 1. Research questions

Verbatim from `EXPERIMENT_PROTOCOL_V2.md` §"Research Questions":

- **RQ1.** Does evidence-escrow EESS improve failure diagnosis versus the open-sharing swarm (S4) at matched budget?
- **RQ2.** What is the cost of centralization (S3 vs S4/S5) in diagnostic accuracy and budget consumption?
- **RQ3.** Which ablations (no-escrow, random selection, no counterfactual, single-agent) cause the largest regressions?
- **RQ4.** Do results transfer to a second, different case (Tox21) at the same budget? `[v1.1: H]` RQ4 is a **no-LLM deterministic transfer study** — see §4.2.

## 2. Falsifiable predictions

Each prediction is stated so that a **negative result is a publishable, expected-capable answer** (SEED_PROMPT "negative results are publishable and expected").

- **P1 (escrow value, RQ1/S5 vs S4).** At matched envelope (identical tokens/wall/agents) and on the **same task/case/oracle** (§3.1), EESS (S5) matches or beats the open-sharing swarm (S4) on the primary metric M1 (correct diagnosis rate, §6), with no budget overrun on either side. *Falsified if:* the pre-registered decision rule below fires. A falsification is reported as: "open sharing already suffices on this case; escrow adds cost without diagnostic value here" — a complete, honest finding.
  - **P1 decision rule (pre-registered; character-identical to §8.1 S4):** "S5 succeeds P1 iff bootstrap 95% CI upper bound of the 10-run interim difference (S5 minus S3 on M1) is < 0, i.e. the entire CI is below zero; otherwise P1 fails and the full 20-run set is reported with the CI." `[v1.1: D]` This single string is the P1 rule in both §2 and §8.1; the v1.0 double definition ("no CI overlap favoring S5" vs "difference CI upper bound < 0") is removed.

- **P2 (centralization cost, RQ2/S3 vs S5).** The adaptive central manager (S3) is not strictly more accurate than S5, or it is more accurate at higher diagnostic latency (median cycle time) or higher token consumption per correct diagnosis (M11). *Falsified if:* S3 strictly dominates S5 on both M1 and M9 latency at equal or lower M6 tokens per run. Falsification is reported as: "centralization pays on this case at matched budget" — also a complete finding.

- **P3 (ablation regressions, RQ3).** **A1 ≤ S5 AND A3 ≤ S5 on M1 (mean counterfactual success) per run-set; bootstrap 95% CI on each difference (10,000 resamples, seed 20261010); effect sizes descriptive only (n=20/arm primary).** `[v1.1: C]` The v1.0 three-way ordinal ("escrow-removal ≥ random-selection ≥ counterfactual-removal") is **removed**: its third term (counterfactual-removal) is the arm A2, which this prereg excludes (D-3) — a 3-way ordinal with one term absent cannot be evaluated. P3 therefore compares only the two ablations that are actually run (A1, A3) against S5. A2 is **excluded from every hypothesis** (it remains an untested arm, labeled as such in §3.2) and appears in no P-statement. *Falsified if:* A1 > S5 or A3 > S5 on M1 (CI lower bound > 0). A falsification identifies which mechanism was load-bearing (or was not) — equally useful.

- **P4 (transfer, RQ4/S5 on Tox21).** The ranking S5 ≥ S4 ≥ A1 holds on the secondary Tox21 case under the same per-arm envelope class. *Falsified if:* the ranking inverts on Tox21. Falsification is reported as: "escrow benefit does not transfer to multi-label toxicity adjudication" — a boundary condition for the mechanism, publishable as such. `[v1.1: H]` P4 is evaluated on the **no-LLM deterministic** Tox21 arm (§4.2); "same budget" is incoherent for a no-LLM case, so P4 is a deterministic transfer check, not a live-token comparison.

If all four are falsified, the honest summary is: "on these cases at this budget, no EESS mechanism is demonstrated; S3/S4 baselines are the recommendation." That is a valid result for this competition entry.

The S5 mechanism is implemented by the following **real** modules (the v1.0 citation to a non-existent orchestrator module is removed in full):

- `repliclaw.needmarket.registry` — the open-need list agents read to make local choices.
- `repliclaw.counterfactual.executor` — `SimpleAuditExecutor` / `run_case`: the real SimpleAudit counterfactual engine (single-factor discipline, `FrozenJudgeClient`, `make_target_fn`).
- `repliclaw.llm.investigators` — `LLMInvestigator` / `LLMClient` / `LLMConfig`: the live-LLM agent layer (endpoint, model, temperature) that the live S5 arm drives.
- `repliclaw.eess_live` (new, in-flight — §13) — the live-LLM EESS orchestration that wires escrow + need-market + counterfactual + live investigators into the arm `eess`.

### 5.2 Parity mechanism (what "matched budget" proves)

Mechanism owner: P05 @ `7fa4f68`, `src/repliclaw/comparators/budget.py`:
1. **Single frozen envelope hash.** All arms in a run are constructed with the identical `BudgetEnvelope` instance; its `sha256()` is recorded in `run_metadata.json`. A parity violation (different envelope hashes across arms of the same case) fails the run — `test_parity_requires_same_envelope` (P05, 19 passing red-first tests). **`[v1.1: B]`** Parity additionally requires the **same Claim/case** across arms (§3.1, C1) — the L12 same-task check.
2. **Hard abort at the envelope.** `BudgetLedger.record()` raises `BudgetOverflow` the moment cumulative tokens/wall/agents exceed the ceiling; the harness aborts the arm mid-run and marks it `aborted_budget` — it cannot silently overrun. `test_ledger_budget_overflow_enforced` covers this. This is the **hard enforcement** the mission requires: the harness, not the model, aborts.
3. **Parity assertion after the run.** `assert_budget_parity(runs)` passes only if all non-aborted runs of the case used the same envelope hash, the same Claim, and none exceeded the ceiling. The report must include the per-arm ledger table (tokens, wall, agent-seconds) so a reader can verify parity from artifacts, not from claims.

**Honest semantics (declared explicitly):** parity of *envelope* (identical ceiling + no overrun) **and of task** (same Claim, C1) is what the mechanism proves. It does **not** prove equal *consumption* — arms may legitimately consume different amounts within the same ceiling (that is a scientific outcome, measured as M5/M6, not a parity failure).

### 5.3 Budget ledger accounting and usage-invalidation (normative)

Tokens are counted at the harness layer from API usage fields (per `EESS_CONTRACTS` §7 artifact contract; P05 ledger API). Wall time is monotonic, measured from arm start to verdict.

**Usage-invalidation rule (new, normative).** `[v1.1: E]` (judge Q13) Any run whose `final_verdict` lacks real usage — i.e. `usage_present < 0.99` of logged LLM calls — is marked `status=invalid_usage`, **excluded from ALL primary metrics**, and **reported in the denominator section with its reason** (the voided-run table, artifact contract §2/§6). The runner harness (`src/repliclaw/comparators/runner.py` + `src/repliclaw/strategies.py::_usage`) **enforces no zero-fill: a missing usage report is an error, not a default.** The v1.0 clause "if a provider omits a usage field, that call is excluded from the campaign (the run is invalidated, not estimated)" is now **implemented, not merely declared**: `strategies.py::_usage` must raise (not return a zeroed `ResourceUsage`) when `client.usage` is absent, and the ledger records `usage_present=false` per call (artifact contract §3). A provider that omits usage can no longer silently under-count tokens and corrupt the matched-budget claim.

## 6. Metrics (exact denominators)

Unit of analysis: one **run** = one arm on one case, executing its protocol to verdict or budget abort. `N_run = 20` (primary, per arm), `N_run = 10` (secondary, per arm). **`[v1.1: E]`** Runs with `status=invalid_usage` are excluded from all primary-metric denominators and reported in the voided-run table (denominator section) with their reason.

| ID | Metric | Definition (exact) | Denominator |
|----|--------|--------------------|-------------|
| **M1** | **Primary — correct diagnosis rate** | Fraction of runs whose final verdict matches the sealed oracle on both defect class and target artifact (policy_rag_v1: `retrieval_omission` on the returns-policy retrieval path; numerator defined identically across arms, §4.1). Secondary (Tox21): per P06 oracle schema @ `859aa4e`, no-LLM. | denominator = `N_run` **per arm** (20 primary / 10 secondary); never pooled across arms; `invalid_usage` runs excluded (reported in voided-run table). |
| **M2** | Falsification discipline | Fraction of preregistered hypotheses that the run attempted to falsify. | denominator = preregistered hypotheses per run. |
| **M3** | Counterfactual yield | Fraction of counterfactual slots executed that produced a verdict change or a falsified hypothesis. | denominator = number of counterfactual slots granted (S5/A1/A3); S0/S3/S4 report `n/a` (no slots by design). |
| **M4** | Leakage incidents | Count of oracle references in arm-side code/paths during the run (re-grep per `EESS_CONTRACTS` §6 at teardown). | denominator = number of runs; any count > 0 voids the affected run (and triggers stopping rule S1). |
| **M5** | Budget consumption (tokens) | Total ledger tokens per run. | per run; reported per arm as mean + range. |
| **M6** | Efficiency — tokens per correct diagnosis | Mean M5 over runs where M1 = 1. | denominator = correct runs per arm; `n/a` if zero correct runs (that itself is a result, reported as such). |
| **M7** | Budget overrun/abort rate | Fraction of runs ending in `aborted_budget`. | denominator = `N_run` per arm. Any arm with abort rate > 25% fails the window for that arm (S0, §8.1) and its envelope-adequacy is a report finding. |
| **M8** | Integrity-rejected artifacts | Count of artifacts rejected by escrow on integrity failure (S5/A3 only; A1 has no escrow). | per run; reported per arm mean. |
| **M9** | Latency to verdict | Wall seconds from arm start to sealed verdict. | per run; per-arm median + IQR. |
| **M10** | Verdict stability | Fraction of runs whose verdict matches the arm's modal verdict across the 20-run block. | denominator = `N_run` per arm. |
| **M11** | Correct-falsified-hypothesis rate | Fraction of preregistered hypotheses that were both falsifiable **and** correctly falsified (oracle-consistent) when the arm ran a falsification attempt. | denominator = number of preregistered falsifiable hypotheses with an attempted falsification, per run. This is the metric the mission names: "fraction of hypotheses correctly falsified per run". |

Primary metric: **M1** (S5 vs S4, RQ1). Secondary metrics: M11, M3, M6, M7, M9. All metrics are computed by the offline scorer only (no arm may compute its own score).

## 7. Runs, statistical plan

### 7.1 Runs per arm and honest justification

- Primary case: **20 runs per arm** (6 arms → 120 runs). Secondary: **10 runs per arm** (60 runs).
- **Justification (resource-constraint statement, NOT a power analysis):** the live window (§9) is bounded by the competition schedule and by the master ceiling in §5.1; 20 × 6 × ~2,600-tokens-observed-floor runs fit with > 10× headroom under the 60k envelope, while 20 runs/arm is the smallest count that lets M10 (stability) and M7 (abort rate) be non-trivial (a 1/20 abort = 5% visible, not a single-sample artifact). We do **not** claim this is powered for any specific effect size; the report will say so. **`[v1.1: Q8]`** The judge confirmed 20 primary / 10 secondary and directed that it **not** be reduced to 10/arm (keep M10 at 20).
- Run-to-run variance control: identical case files, identical envelope, identical model endpoint settings (below); LLM sampling is **not** seed-controllable at the endpoint (declared), so run-to-run variance on live calls is an inherent property of the experiment and is exactly what M10/M2 capture. Deterministic components (engine, interventions, scoring, A3's random ranking) use fixed seeds (§10.2).

### 7.2 Statistical plan (pre-registered, no post-hoc choice)

- **Unit of analysis:** the case, not the run. With **n_cases = 1** for the primary comparison, **no inferential test is reported** for S5-vs-S4 on the primary case; the primary comparison is **descriptive** (point estimates + 95% CIs) with run-level bootstrap only as a within-case uncertainty device. This is a declared limitation, not a power claim.
- **Bootstrap (within-case):** 10,000 resamples of runs, seeded `20261010` (the harness seed), per arm; report arm-level M1 as point estimate with percentile 95% CI from the bootstrap; the S5-vs-S4 difference is reported with its bootstrap CI. **`[v1.1: D]`** The P1 decision rule is the single pre-registered string in §2 (character-identical to §8.1 S4): "S5 succeeds P1 iff bootstrap 95% CI upper bound of the 10-run interim difference (S5 minus S3 on M1) is < 0, i.e. the entire CI is below zero; otherwise P1 fails and the full 20-run set is reported with the CI." No p-value is the decision basis.
- **`[v1.1: C]`** For P3, the bootstrap 95% CI is computed on **each** of the two differences (A1 − S5 and A3 − S5) with 10,000 resamples, seed `20261010`; effect sizes are **descriptive only** (n=20/arm primary).
- **Case-level inference (RQ4, when Tox21 lands):** with n_cases = 2, the *only* inferential statement allowed is a sign-consistency check across the two cases for each ranking claim (e.g., S5 ≥ S4 in both cases), reported descriptively. **No paired t-test, no McNemar, no effect-size inference across 2 cases** — any such number would be over-claiming; the feasibility-stage McNemar (p = 0.009, F05) belongs to the *feasibility* artifact, not to this prereg's conclusions.
- **Aborting as missing data:** `aborted_budget` runs are reported in M7 and **excluded** from M1 denominators with the exclusion stated per arm (not pooled away). **`[v1.1: E]`** `invalid_usage` runs are likewise excluded from all primary denominators and reported in the voided-run table. Sensitivity analysis: recompute M1 including aborts as failures; report both.
- **One-sided vs two-sided:** N/A for the primary (descriptive). The pre-registered decision rule above is effectively one-sided for "supports" and two-sided for "falsifies"; the report must state which branch fired.
- **Alpha:** not applicable (no NHST on primary). For the case-level sign check, none is claimed. This plan is fixed; the judge approves or rejects it wholesale (REVIEW Q6).

## 14. Scorer contract

**`[v1.1: J]`** `repliclaw.p08.score` is the **sole oracle reader**, invoked **post-seal** (only after every run directory's artifacts exist). It is the only code path that reads an oracle (artifact contract §5); any arm-side code reading an oracle path is a leakage incident (M4 > 0 ⇒ campaign stop S1). Requirements:

- **(a) Post-seal oracle access:** loads the oracle **only after** arm artifacts are sealed.
